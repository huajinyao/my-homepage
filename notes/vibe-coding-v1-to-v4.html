从 V1 到 V4：一个人主页的迭代复盘

滑锦尧 · 2026-10 · 学习笔记 03

这篇笔记记录我的个人主页从 V1 到 V4 到底改了什么、为什么改。写下来的原因很实际：如果不复盘，下一版大概率会重复上一版的错误。

V1：先让它能打开

V1 的目标只有一个——一个能预览、内容真实、结构清楚的 MVP。浅色背景，CSS Grid 卡片，顶部导航，移动端折叠菜单。

当时做了一个关键取舍：没有合适的照片，头像就用字母徽标「滑」占位，而不是去网上找一张图凑数。这条「不虚构」的原则后来一直保留。

V2：从「能用」到「像我」

V1 的问题是任何人都能做出 V1。V2 参考了 CodePen 上的 The Neural Network Hero Banner（作者 Kuldeep Rajput），把整体换成深色科技风：背景 #0a0e14，主色 #00e5ff，名字发光，Canvas 粒子网络。

选深色不是我一时兴起——智能医学工程（脑机接口）这个方向本身就带着「信号、神经、设备」的气质，深色加青蓝比浅色更贴。

移动端性能是这一版最实际的问题

粒子网络在电脑上很漂亮，在手机上直接卡死。解决办法是按屏幕宽度动态降级，而不是简单删掉效果：

< 480px2080px30fps

AI 当时建议把粒子网络换成静态 SVG 或纯 CSS 渐变，我拒绝了——视觉效果是这版的核心，应该优化参数而不是砍掉功能。

V3：让它有功能

V3 加了三个东西：滚动淡入（Intersection Observer，比监听 scroll 性能好）、打字机效果、留言板。

留言板用 localStorage，key 是 huajinyao_guestbook，最多显示 20 条。所有用户输入在渲染前都过一遍 escapeHtml，否则一个 <script> 就能把页面打穿。这一版也补了空状态提示。

AI 建议上 Supabase 做真后端。当时判断：课程作业阶段没有真实多人留言的需求，localStorage 已经够用，引入后端只会增加部署和密钥管理的复杂度。这个判断在期末被推翻了——因为数字分身必须有一个服务端来藏 API Key。

V4：补齐身份与细节

V4 是内容层面的补齐：双校身份卡片、校园资源链接、成长轨迹时间线、音乐播放器（20 首）、技能雷达图、中英切换、明暗主题切换、访问量统计。

这一版也开始做减法：修掉了几个失效链接，压掉了首屏不必要的资源加载（CSS 改成 media="print" 异步加载），移动端字号统一。

期末版：把「数字分身」做成真的

期中时数字分身只是个占位——9 条关键词匹配，问「你导师是谁」就直接兜底。期末换成了真正调用 DeepSeek 大模型的实现，前后端都重写了。

详细的技术细节写在另一篇笔记里：《我是怎么把数字分身做成真的》。

回头看，三条有用的经验

  1. 先定「不能做什么」，再定「要做什么」。V1 的「不虚构」原则省掉了后面很多返工。
  2. AI 的建议要带着约束听。它不知道你的手机有多卡，也不知道你愿不愿意管一个数据库。
  3. 先能用，再好看，最后才是聪明。顺序反了会一直推倒重来。
